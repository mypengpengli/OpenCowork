# 自动执行、审阅和经验复用

这轮功能在本地 Rust 运行时中实现，不需要智谱、Codex 或 Hermes 的托管服务。模型仍使用你在 Provider 中配置的 API。浏览器工具需要本机安装 Chrome 或 Edge；电脑控制支持 Windows。

## 使用入口

- 对话下方的“目标、补充要求与消息队列”：勾选后，本次消息成为持续执行的目标。目标会要求 UpdatePlan 和实际工具证据，再由独立请求检查是否完成。默认最多 12 轮、500000 tokens；暂停、预算耗尽或异常后保留进度，点击恢复继续。
- 同一区域可在运行中补充要求，或将消息排入下一轮。补充要求在两次模型请求之间注入，队列在当前回合完成后处理。稳定消息 ID 和会话独占租约用于避免重复投递和并发写入。
- “接管电脑并停止任务”暂停电脑操作并停止本窗口的活动任务；“允许继续电脑操作”恢复操作权限。恢复后须重新观察窗口。其他应用窗口仍在同一个 Windows 活动桌面上。
- “审阅更改与恢复”：选择工作区文件后，可以按文件或分块暂存、取消暂存，以及撤销未暂存的普通文本更改。恢复点保存操作前内容。文件改变后，旧审阅版本会被拒绝。分块暂不处理二进制、重命名、新增或删除文件；完整暂存支持新增文件。
- “历史全文搜索”：搜索正文、工具结果和压缩归档，支持中文子串。默认只查当前项目；旧版没有项目归属的会话需勾选包含其他项目。结果包含来源会话、消息位置、摘要和匹配消息原文。
- “记忆来源与冲突”：自动提取的事实包含来源会话和时间。同标题的新事实先成为冲突，用户选择保留原记忆或采用新事实。相同事实去重，手动删除的已知自动事实不会立即重新生成。
- “可复用技能候选”：审阅当前版本、候选步骤、完成检查、失败恢复和来源证据；可采用、拒绝或停用。候选来自至少两项成功观察，模型生成的步骤仍应审阅，不能视为经过所有场景验证的脚本。
- “定时任务与结果收件箱”：按间隔或每天指定时区执行。使用 IANA 时区名称，例如 `Asia/Shanghai`；夏令时不存在的时间跳过，重复时间只采用第一次。默认跳过错过超过一分钟的执行，也可选择补一次。异常或取消后暂停；中途退出后标记结果未知，不自动重放。
- “隔离工作区”：从当前 Git HEAD 创建独立 worktree 和 `cowork/名称` 分支。未提交更改保留在原项目。用新路径启动独立工作区或作为子任务工作目录；不会自动复制原项目的密钥和本地配置，也不自动合并或删除 worktree。

## 设置与预算

设置 → 权限 → 自动执行与模型能力：

| 项目 | 默认值 |
| --- | --- |
| 回合迭代上限 | 80 |
| 回合 token 上限 | 250000 |
| 整个前台任务时间上限 | 900 秒 |
| 连续相同动作和结果停止阈值 | 3 |
| 单次输出 token 上限 | 8192 |
| 浏览器工具 | 开启 |
| 电脑控制 | 开启 |
| 后台记忆提取 | 关闭 |
| 技能候选生成、自动采用 | 均关闭 |

后台模型名称可与前台不同，使用同一个已配置 Provider。推理强度仅在用户选择时发送 `reasoning_effort`，兼容性取决于服务端。模型诊断最多发起四次小请求，分别检查连接、工具调用、图像识别和流式返回，显示耗时和用量；它不是模型任务成功率评测。本版协议为 Chat Completions，不声称已支持原生 Responses 或 Anthropic Messages。

缓存读写和普通输入分别记录，合计不重复计算。服务端缺失 usage 时无法精确执行 token 上限，时间及迭代上限仍有效。停止条件在模型请求之间和工具执行前检查；单次模型调用可能超过剩余 token 预算。目标检查、事实提取和技能提取的额外用量在各自状态中显示，价格未知时不推算金额。

仅连接建立失败，以及尚未流式输出的 HTTP 429/503 会自动重试一次。流中断、超时和已提交的工具动作不会自动重放。

## 恢复与边界

工具意图、工具结果和补充消息先经过父进程落盘确认，再继续执行；文本增量定期检查点保存。强制结束宿主后，重启会恢复检查点，并将未收到结果的动作标为结果未知。工具实际动作与本地记录无法成为一个跨应用事务，因此仍须先观察，不能把“没有成功回执”理解为“动作没有发生”。

文件工具的 workspace-write 限制覆盖绝对路径、父目录穿越、已有父目录、符号链接／junction 跳转和 NTFS 数据流。它不是任意 shell、MCP 或网络访问的操作系统沙箱。恢复快照和内容版本检查能拒绝已经观察到的并发修改；外部编辑器在最终检查与替换之间写入仍属于文件系统竞争边界。

电脑助手由每个聊天工作进程持有，首次启动后复用原生类型，超时或取消终止其进程树。浏览器为独立无头实例，标签页属于当前工具运行时，不导入个人浏览器登录态。跨进程 iframe、文件上传、复杂站点登录和跨回合浏览器持久化未作为本轮验收项。

定时器需要 OpenCowork 宿主保持运行，不是 Windows 关机后的系统任务服务。本版只交付本地收件箱，不向邮件或即时通信软件自动发送消息。同一配置目录最多有一个定时工作进程；不同宿主争用同一任务由磁盘租约防止重复认领。

## 验证

`scripts/check-optimizations.py` 使用临时项目、测试文件和本地模型替身验证写入范围、缓存计数、停滞／预算、目标证据、队列去重、技能采用／停用、分块恢复、中文检索、独立浏览器表单／响应式尺寸／iframe／诊断、电脑助手复用、接管、定时执行、宿主崩溃恢复。

`scripts/check-chat.py`、`scripts/check-features.py` 和 `scripts/check-computer-window.ps1` 覆盖原有流式与取消、截图传入模型、记忆来源／冲突、Windows 原生输入和遮挡窗口捕获。真实多屏混合 DPI、全新机器安装，以及外部模型在真实网站上的任务成功率仍需实机验证；不以本地替身测试宣称与其他产品等效。
