# Phase 17 Report

## Scope

This phase continued direct parity work against:

1. `claude-code-best/claude-code`
2. `ChinaSiro/claude-code-sourcemap`

The focus was moving session memory closer to the reference repositories' background-maintained model.

## Delivered

- Added `hydrate_current_session_memory` so prompt preparation reloads the latest persisted session-memory file before context optimization.
- Added background session-memory scheduling:
  - [session_memory.rs](d:\新建程序项目\opencowork\crates\runtime\src\session_memory.rs)
  - `maybe_schedule_session_memory_refresh`
  - `maybe_schedule_session_memory_refresh_with_config`
- Switched app/CLI turn completion paths to schedule session-memory refresh in a background thread instead of synchronously refreshing it in the foreground.
- Updated prompt preparation to hydrate session memory before:
  - instruction collection
  - context optimization
  - session-memory-aware compaction
- Added regression coverage for background scheduling and persisted file creation.

## Remaining gaps

- Session memory is now background-scheduled, but the content is still generated by the local renderer rather than a forked model-side extractor.
- The background path does not yet expose explicit completion/failure events into the UI/event stream.
- Team-memory watcher/sync behavior is still missing.
- Relevant-memory selection still lacks a dedicated side-query provider/model path.
